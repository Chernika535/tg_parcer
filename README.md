# Telegram Feed Aggregator

PWA для агрегации публичных Telegram-каналов и рассылки сводок по ключевым словам.

- **Чтение каналов** — только парсинг публичной веб-версии `https://t.me/s/<channel>` (без MTProto, без аккаунтов, без номеров).
- **Доставка сводок** — Telegram Bot API (бот только отправляет, ничего не читает).
- **Планировщик** — внешний крон (cron-job.org) дёргает защищённый `/api/cron`.
- **Хостинг** — Onreza (бесплатный тариф). Бюджет — ноль.

Однопользовательское приложение, данные хранятся локально в браузере.

> ## ⚠️ Важно: приложение полностью клиентское (без бэкенда)
>
> Onreza на бесплатном тарифе в этом проекте **не запускает сборку и не имеет
> настроек** — он просто отдаёт готовую статику из папки `dist/`. Поэтому всё
> работает в браузере:
> - **Чтение каналов** — `t.me/s/<channel>` через бесплатный публичный CORS-прокси
>   (прямой запрос из браузера блокирует CORS).
> - **Хранение** лент / парсингов / настроек — `localStorage`.
> - **Отправка сводок** — Bot API прямо из браузера (`api.telegram.org` отдаёт CORS).
>   Токен бота хранится только в вашем браузере (вводится в «Настройках»).
>
> Папка `dist/` **закоммичена в репозиторий** — Onreza берёт её как есть.
> **После любого изменения исходников пересоберите и закоммитьте `dist/`:**
> ```bash
> npm run build && git add -A && git commit -m "rebuild" && git push
> ```
>
> Папки `api/` и `db/` — опциональный серверный вариант (для платформ с
> serverless-функциями и Postgres). В текущем статическом деплое не используются.

## Стек

Vite + React + TypeScript (SPA, PWA) · serverless-функции Onreza (Web `Request`/`Response`) ·
PostgreSQL (postgres.js) · Onreza KV · `node-html-parser` · `vite-plugin-pwa`.

## Структура

```
db/        schema.sql + migrate.ts (идемпотентные миграции)
api/       serverless-функции
  _lib/    db, kv, scraper, telegram, feed, digest, auth, util
src/       фронтенд (pages, components, styles)
public/    PWA-иконки
scripts/   gen-icons, test-scraper, test-parse
```

## Локальная разработка

```bash
npm install
cp .env.example .env      # заполнить DATABASE_URL, TELEGRAM_BOT_TOKEN, CRON_SECRET
npm run migrate           # применить схему
npm run dev               # фронтенд (Vite)
```

Проверки скрапера:

```bash
npm run test:parse        # оффлайн: парсинг HTML-фикстуры
npm run test:scraper telegram   # онлайн: реальный канал (нужен доступ к t.me)
```

> Примечание: в некоторых окружениях исходящий доступ к `t.me` закрыт политикой —
> тогда живой `test:scraper` не пройдёт, но `test:parse` подтверждает логику разбора.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения managed Postgres (выдаёт Onreza) |
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather (на фронт не отдаётся) |
| `CRON_SECRET` | длинная случайная строка, защищает `/api/cron` |
| `APP_USER_ID` | `local` — единственный пользователь |
| `APP_BASE_URL` | публичный URL приложения на Onreza |

KV доступен через `@onreza/runtime/kv` без отдельной переменной.

## Деплой (статический, без настроек)

1. `npm run build` — создаёт `dist/` (фронт + SPA-фоллбэк `404.html` и `_redirects`).
2. Закоммитить и запушить весь репозиторий, включая `dist/`.
3. Onreza подхватывает `dist/` как готовую статику. Никаких build-команд, переменных
   окружения и БД настраивать не нужно.

## Подключение Telegram

1. Создать бота у @BotFather, получить токен.
2. В «Настройках» вставить токен и нажать ОК.
3. Открыть бота, отправить `/start`, затем «Определить chat_id».
4. Фоллбэк: ввести `chat_id` вручную (взять у @userinfobot).

## Известные ограничения

- `t.me/s/` отдаёт только последние ~20 постов и только для каналов с включённым превью.
  Истории вглубь нет; канал без превью / приватный не читается — это вне рамок проекта
  (в ленте помечается как недоступный, ленту не ломает).
- Парсинг по HTML хрупкий: при смене вёрстки Telegram чинится по логам скрапера
  (`// SCRAPER: markup changed?`).
- Чтение зависит от стороннего CORS-прокси (бесплатные публичные, с фоллбэком). Если
  прокси недоступен/лимитирован — канал помечается как недоступный. Кэш ответа 10 мин.
- Данные (ленты, парсинги, токен, chat_id) живут в `localStorage` конкретного браузера
  и не синхронизируются между устройствами. Очистка данных сайта их удалит.
- **Сводки по расписанию не работают** — на статическом хостинге нет фонового
  планировщика. Сводку можно собрать и отправить вручную кнопкой «Запустить сейчас».
  (Для автоматической рассылки нужен бэкенд/внешний крон — см. серверный вариант в `api/`.)
- Фильтр сводок — по подстрокам ключевых слов. Без смысловой фильтрации и
  LLM-суммаризации (платно, вне бюджета).
- Поиск только по добавленным каналам, не по всему Telegram.
